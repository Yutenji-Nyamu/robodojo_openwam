## 为什么之前选2×N

9月28日简单叠碗实测：W2/N4约8.52动作/秒、68.39GiB；W1/N16约5.18动作/秒、43.28GiB。双worker当时能提高整卡吞吐，但两组布局/回合数并不一致，不能视为严格最优证明。双worker重复加载模型与仿真，对复杂场景估计余量不足；后续深圳3π0.5在W2/N4达到99%并发生真实OOM。旧W1/N25为1800秒测量超时，不能记成OOM。

本轮用同任务同50回合补更公平的单worker扩容曲线。官方50回合在N9/16/25/36下分别约6/4/2/2批；N36第二批只有14个有效环境，必须将尾批利用率计入真实完成时间。显存不是唯一约束，图像回传、逐环境IK、物理/渲染及末尾慢环境均可能限制收益。

参考：旧测试（包外本地来源：`PARALLEL_TEST_20260928.md`，未随包提供）、[今日N4/N9](PARALLEL_GPU3_20261003.md)、[原生评估入口](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/main/scripts/README.md)、[Isaac5.1性能手册](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/reference_material/sim_performance_optimization_handbook.html)。这一轮只改并行数，不调整物理步长/画质等影响评估条件的参数。

## 源码可确认的扩容取舍

- OpenWAM有效环境一起调用`generate_batch`，存在真实模型batch收益；随后动作转换仍逐环境。π0.5适配内部循环调用单环境`policy.infer`，不能套用本轮OpenWAM结果。
- OpenWAM的32动作chunk仅减少模型前向次数；chunk内仍逐动作更新观测、读取三路图像、录像和RPC。相机路径对完整N图重排并读回CPU，然后取有效环境。
- EEF控制逐环境逐臂做IK，部分状态getter先复制全N状态再取单环境；这是增大N的潜在成本，尚未量化各阶段耗时占比。
- 结束环境不立即填新回合，整批全部结束后close/reset；结束环境的场景和相机仍在。N36相对N25同为两批50回合，没有减少批次数的优势，可能更受尾批/慢环境影响。
- 决策以整项完成速度和余量为主；70GiB只是本次硬停止线，不是建议长期目标。后续正式候选仍需留复杂任务余量，并单独验证π0.5/random，不能凭单任务零故障宣称全套稳定。
