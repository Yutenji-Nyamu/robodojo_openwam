# OpenWAM单worker：N4与N9实测

2026-10-03在深圳1物理GPU3独立完成，同一权重、标准叠碗stack_bowls、seed0、layout0–8各9回合；先N9后N4。正式4–7继续，配置及源码没有改变。

| 配置 | 完成/成功 | 总耗时 | 显存峰值 | 实际动作 |
|---|---|---|---|---|
| W1/N4 | 9/8 | 18分45秒 | 36.06GiB | 3782 |
| W1/N9 | 9/9 | 12分15秒 | 37.39GiB | 3133 |

N9仅多占1.33GiB，本次九回合耗时减少34.7%、回合吞吐为N4的1.53倍。N4有一个layout达到800步失败，累计动作比N9多649步；两次轨迹不同，不能把全部耗时差归因于N，也不能由9/9与8/9断言N9改善成功率。

结论：单worker提高环境数有实测价值；此前W2/N4的OOM不能直接推导W1/N9也装不下。此处两组均正常退出，无GPU致命错误，两次清理后卡健康空闲；共18条结果、54份三路录像完整，全部视频640×480且有帧，每组抽4份视频解码通过。N9首尾布局头部图目视通过。最终GPU3为3MiB/recovery None、所属进程0。

本轮仅标准叠碗的一次对照。复杂random任务官方默认封顶5环境，π0.5内部逐环境推理，因此不直接把本结果推广到两模型全任务。当前正式W1/N4保持；后续若继续提速，应先验证较复杂任务和π0.5自身收益，优先测试W1增加环境数。

历史明确OOM发生于深圳3 π0.5 GPU5的W2/N4，NVTT cudaMalloc分配失败，显存采样峰80712/81559MiB；两个worker重复两套模型/仿真。N9只一套模型，本轮峰38284MiB。低占用CUDA700仍属于独立问题。

统计说明：N9初始计数器遗漏ANSI颜色过滤，误报零动作；仿真连续运行至正常退出。保留原错误状态，独立从原始日志核env0–8、3133动作，并核9结果及退出/清理后才启动N4。未重跑N9、未修改物理/模型；完整N9动作窗口时间戳不足，故不报告两组动作阶段利用率对比。

资源/协议保持：一worker，模型与仿真同卡；3路640×480、25Hz、物理dt0.004、动作chunk32、denoise10。每组1800秒上限，致命错误不重试。测试结果不并6300正式成绩。
